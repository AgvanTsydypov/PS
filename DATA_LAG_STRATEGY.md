# ⏰ Стратегия задержки загрузки данных (Data Lag Strategy)

## 🎯 Концепция

Разные типы данных загружаются с разной временной задержкой для обеспечения полноты и точности:

### Группа 1: Свежие данные (текущий день)
- **Events** - события и рынки
- **Markets** - рыночная информация

### Группа 2: Данные с задержкой (3 дня назад)
- **Redemptions** - выплаты пользователям
- **Positions** - закрытые позиции
- **Leaderboard** - рейтинги трейдеров

---

## 🤔 Почему задержка в 3 дня?

### Проблема без задержки
```
День 1 (2026-01-06):
├─ Событие закрывается
├─ Победитель определен
└─ НО: Пользователи еще не забрали выигрыши!
    └─ Redemptions: 0 записей ❌

День 2 (2026-01-07):
└─ Некоторые забрали, но не все
    └─ Redemptions: 30% от ожидаемого ⚠️

День 3 (2026-01-08):
└─ Больше пользователей забрали
    └─ Redemptions: 70% от ожидаемого 📊

День 4 (2026-01-09):
└─ Большинство забрали выигрыши
    └─ Redemptions: 95%+ от ожидаемого ✅
```

### Решение: Задержка в 3 дня
```
Сегодня: 2026-01-09 (День 4 сезона)

STEP 1: Events
└─ Загружает свежие события: 2026-01-09
    └─ События, которые закрылись сегодня

STEP 2-4: Redemptions, Positions, Leaderboard
└─ Загружает данные 3 дня назад: 2026-01-06
    └─ К этому времени большинство забрали выигрыши
    └─ Данные почти полные (95%+)
```

## 🔄 График накопления данных

### События за 10 дней сезона

```
Season 1: 2026-01-06 → 2026-01-15

День | Дата       | Events загружены | Redemptions (для какой даты)
-----|------------|------------------|-----------------------------
1    | 01-06      | 01-06            | - (нет данных старше 3 дней)
2    | 01-07      | 01-07            | - (нет данных старше 3 дней)
3    | 01-08      | 01-08            | - (нет данных старше 3 дней)
4    | 01-09      | 01-09            | 01-06 (3 дня назад) ✅
5    | 01-10      | 01-10            | 01-07 (3 дня назад) ✅
6    | 01-11      | 01-11            | 01-08 (3 дня назад) ✅
7    | 01-12      | 01-12            | 01-09 (3 дня назад) ✅
8    | 01-13      | 01-13            | 01-10 (3 дня назад) ✅
9    | 01-14      | 01-14            | 01-11 (3 дня назад) ✅
10   | 01-15      | 01-15            | 01-12 (3 дня назад) ✅
```

### Итоговая картина после сезона

```
После Season 1 (01-15):

Events:
└─ Все 10 дней: 01-06, 01-07, ..., 01-15 ✅

Redemptions, Positions, Leaderboard:
└─ 7 дней из 10: 01-06, 01-07, ..., 01-12 ✅
└─ Последние 3 дня: 01-13, 01-14, 01-15 ⏳ (загрузятся в следующем сезоне)
```

## 📈 Преимущества

### ✅ Полнота данных
- Redemptions: 95%+ пользователей уже забрали выигрыши
- Positions: Окончательные расчеты завершены
- Leaderboard: Стабильные рейтинги

### ✅ Точность
- Меньше изменений в исторических данных
- Финальные цифры PnL и volume
- Корректные позиции в рейтинге

### ✅ Эффективность
- Не нужно перезагружать данные
- Один раз загружено = окончательно
- Меньше нагрузки на API

```
День 2 (01-07):
├─ Events: ✅ Загружены за 01-07
└─ Остальное: ⏭️ Пропущены

День 3 (01-08):
├─ Events: ✅ Загружены за 01-08
└─ Остальное: ⏭️ Пропущены

День 4 (01-09):
├─ Events: ✅ Загружены за 01-09
└─ Redemptions/Positions/Leaderboard: ✅ Загружены за 01-06 (3 дня назад)
```

### Конец сезона (последние 3 дня)

```
Season 1 заканчивается: 2026-01-15

День 10 (01-15):
├─ Events: ✅ Загружены за 01-15 (последний день сезона)
└─ Redemptions: ✅ Загружены за 01-12 (3 дня назад)

└─ Данные за 01-13, 01-14, 01-15 загрузятся в начале Season 2

```

```
Season 2: 2026-01-16 → 2026-01-25

День 1 Season 2 (01-16):
├─ Events: ✅ Загружены за 01-16 (Season 2)
└─ Redemptions: ✅ Загружены за 01-13 (еще Season 1, 3 дня назад)
    └─ Используются события из Season 1!

День 2 Season 2 (01-17):
├─ Events: ✅ Загружены за 01-17 (Season 2)
└─ Redemptions: ✅ Загружены за 01-14 (еще Season 1, 3 дня назад)

День 3 Season 2 (01-18):
├─ Events: ✅ Загружены за 01-18 (Season 2)
└─ Redemptions: ✅ Загружены за 01-15 (последний день Season 1)

День 4 Season 2 (01-19):
├─ Events: ✅ Загружены за 01-19 (Season 2)
```

## 🔧 Настройка задержки

### Изменить количество дней задержки

```python
# В scripts/daily_scheduler.py

# Текущая настройка: 3 дня
LAG_DAYS = 3

# Можно изменить:
LAG_DAYS = 1  # Меньше задержка, но данные могут быть неполными
LAG_DAYS = 5  # Больше задержка, данные полнее, но медленнее
LAG_DAYS = 7  # Максимальная полнота, но сильное отставание
```

### Рекомендации по выбору задержки

| Задержка | Полнота данных | Актуальность | Рекомендация |
|----------|----------------|--------------|--------------|
| 0 дней   | 30-50%         | Максимальная | ❌ Не рекомендуется |
| 1 день   | 50-70%         | Высокая      | ⚠️ Для тестов |
| 2 дня    | 70-85%         | Хорошая      | ⚠️ Минимум |
| **3 дня**| **85-95%**     | **Отличная** | ✅ **Оптимально** |
| 5 дней   | 95-99%         | Средняя      | 📊 Для анализа |
| 7 дней   | 99%+           | Низкая       | 📚 Для истории |

## 📊 SQL запросы для проверки

### Проверить полноту данных

```sql
-- События vs Redemptions по датам
SELECT 
    e.end_date::date as event_date,
    COUNT(DISTINCT e.id) as events_count,
    COUNT(DISTINCT r.id) as redemptions_count,
    COUNT(DISTINCT r.redeemer_address) as unique_redeemers
FROM events e
LEFT JOIN markets m ON e.id = m.event_id
LEFT JOIN redemptions r ON m.condition_id = r.condition_id
WHERE e.end_date::date BETWEEN '2026-01-06' AND '2026-01-15'
GROUP BY e.end_date::date
ORDER BY event_date;
```

### Проверить задержку загрузки

```sql
-- Когда были загружены данные
SELECT 
    load_date,
    events_loaded,
    redemptions_loaded,
    positions_loaded,
    leaderboard_loaded,
    events_loaded_at,
    redemptions_loaded_at
FROM season_data_loads
WHERE season_name = 'season1'
ORDER BY load_date;
```

### Найти пропуски в данных

```sql
-- Дни с событиями, но без redemptions
SELECT 
    e.end_date::date as missing_date,
    COUNT(e.id) as events_without_redemptions
FROM events e
LEFT JOIN markets m ON e.id = m.event_id
LEFT JOIN redemptions r ON m.condition_id = r.condition_id
WHERE e.end_date::date BETWEEN '2026-01-06' AND '2026-01-15'
  AND r.id IS NULL
GROUP BY e.end_date::date
HAVING COUNT(e.id) > 0;
```
